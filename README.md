# PPT Workflow

按模板规划内容、按需编写讲稿，并通过反馈持续完善的 PPT 制作工作流。

`ppt-workflow` 将演示文稿制作分为需求梳理、模板分析、内容编写、语言优化、制作和检查几个阶段。你可以只要求一份逐页大纲，也可以提供材料与模板，让工作推进到完整成品。

## 核心约定

- **模板优先**：先理解你提供的模板、参考页面和排版要求，再编写适配的内容。
- **讲稿按需**：需要逐字稿、讲解提示或演讲者备注时才生成。
- **语言分两轮优化**：先精简论证和多余限定，再调整中文语气与节奏，最后复核事实。
- **按任务阶段交付**：只要求计划时完成计划；要求制作时继续完成成品和检查。
- **长期偏好可更新**：明确要求长期采用的做法写入技能，单次项目的特殊要求留在当前任务中。

## 工作流程

| 阶段 | 主要工作 | 输出 |
| --- | --- | --- |
| 1. 明确任务 | 梳理主题、受众、评分要求、时长、交付格式与当前阶段 | 任务目标与约束 |
| 2. 查看模板 | 分析页面结构、文字容量、图表位置、字体配色与保留元素 | 内容需要遵循的版式 |
| 3. 整理材料 | 阅读资料、核验依据，确定叙述主线和各部分重点 | 整体框架与资料依据 |
| 4. 编写逐页内容 | 确定每页任务、文字、图表、排版和时间安排 | 可用于制作的逐页文案 |
| 5. 优化语言 | 依次应用两个文字技能，并复核概念、数字和来源 | 清楚、自然的页面表达 |
| 6. 制作排版 | 按模板和交付格式完成页面 | 演示文稿及所需辅助材料 |
| 7. 检查调整 | 检查内容覆盖、版式、可读性、来源和讲述节奏 | 完成检查的交付版本 |

讲稿是可选环节。没有讲稿需求时，直接围绕页面内容推进制作与检查。

如果中途补充模板，会重新调整已有内容的长度、图形和分页，让内容适配新要求。没有模板时，再根据汇报场景制定视觉方案。

## 使用前准备

本项目提供工作流规则。使用时，需要在你的技能环境中加载本项目，并准备以下配套能力：

| 配套技能或能力 | 用途 | 使用条件 |
| --- | --- | --- |
| `anti-defensive-writing` | 精简铺垫、重复限定和防御性表述，明确观点与范围 | 页面文案及可选讲稿的语言优化 |
| `humanizer-zh` | 调整中文语气、句子节奏和连接方式，减少空泛表达 | 页面文案及可选讲稿的语言优化 |
| 适用的演示文稿制作技能或工具 | 生成、预览和检查 PPTX、HTML 等交付文件 | 需要制作成品时 |
| `skill-creator` 及其校验工具 | 检查技能结构，支持后续维护 | 环境提供时使用 |

本仓库不包含这些配套技能或文件生成工具，也不会自动安装它们。具体成品格式取决于运行环境提供的能力。缺少配套技能时，应明确说明缺项及其影响。

## 使用示例

加载技能后，可以按下面的方式提出需求。

### 先制定计划

```text
使用 $ppt-workflow，帮我规划一份课程汇报 PPT。
主题是数据开放与数据安全，汇报时长约 6 分钟。
先给出整体框架和逐页安排，暂不制作文件。
```

### 按模板制作

```text
使用 $ppt-workflow，根据我提供的资料和 PPT 模板制作演示文稿。
先分析模板里的标题、正文和图表区域，再编写适配的内容。
保留模板的字体、配色和页脚。本次不需要讲稿。
```

### 补充讲解提示

```text
使用 $ppt-workflow，为现有 PPT 补充简短的讲解提示。
每页说明重点和过渡，不需要逐字稿。
```

### 中途更换模板

```text
使用 $ppt-workflow，把已经确定的内容适配到这份新模板。
保留论证主线，根据新版式调整文字量、图表和分页。
```

## 逐页大纲包含什么

逐页规划会按任务需要说明：

- **页面任务**：这一页回答什么问题，怎样承接前后页。
- **页面文字**：标题、核心观点、必要正文和来源标记。
- **图表与素材**：展示什么关系、数据或实例，依据是什么。
- **排版方式**：采用哪个模板页面，各区域放什么，重点在哪里。
- **时间安排**：根据整体时长分配讲述重点，并标明估算时间。

页数、配色、案例和页面类型根据具体项目确定。实际试讲时间与估算时间分开记录。

## 语言优化方式

第一轮使用 `anti-defensive-writing`，让观点更直接、范围更清楚，保留影响准确性的必要条件。

第二轮使用 `humanizer-zh`，调整中文句式和语气，用具体用途、观察和判断替代空泛总结。

两轮修改后，再核对事实、术语、数字和来源，检查文字是否仍适配版式。个人观点应符合使用者的真实想法，假设场景和示意数据需要标明。

## 持续维护

你可以在后续使用中直接提出新的长期要求，例如：

```text
更新 $ppt-workflow：以后制作 PPT 时，先检查模板的页面比例，
并在逐页规划中注明每页采用的模板页面类型。
```

维护时会定位并修改相关规则，合并重复内容，清理冲突，更新版本与日期，并检查技能结构。

| 反馈方式 | 处理范围 |
| --- | --- |
| “以后都这样”“加入工作流”“更新这个 skill” | 更新技能中的长期规则 |
| “这次用蓝色”“本次控制在 8 页以内” | 仅用于当前项目 |
| “先讨论一下”“暂时不要修改” | 整理建议，暂不写入技能 |

更新由后续明确需求触发，不包含后台监控或定时任务。修改技能与更新项目文件、同步远程仓库分别处理，按当次要求执行。
